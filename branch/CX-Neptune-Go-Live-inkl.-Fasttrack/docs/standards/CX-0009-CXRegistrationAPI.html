CX-0009 CX Registration API v2.1.0

ABSTRACT​

This standard defines the Registration APIAPI An API is a way for two or more computer programs to communicate with each other. for the Catena-X network. It specifies the endpoints that a Core Service Provider B must implement to enable prospective participants to register.

1. Introduction​

To become a participant of Catena-X, each prospective participant must go through a registration process. Registration is a mandatory requirement for all further activities within the Catena-X network. The registration process, along with other services, provides the foundation of trust for the Catena-X network.

1.1 Audience & Scope​

This section is non-normative

This standard is relevant for the following roles:

  • Core Service Provider B
  • Onboarding Service Provider

1.2 Context​

This section is non-normative

The registration APIAPI An API is a way for two or more computer programs to communicate with each other. is used as part of the registration process.

1.3 Interactions​

This section is non-normative

A Core Service Provider B operates a registration APIAPI An API is a way for two or more computer programs to communicate with each other. through which a registering company can enter its data. The registration service may be accessed by an Onboarding Service Provider, on behalf of a registering company.

1.4 Conformance​

As well as sections marked as non-normative, all authoring guidelines, diagrams, examples, and notes in this specification are non-normative. Everything else in this specification is normative.

The keywords MAY, MUST, MUST NOT, OPTIONAL, RECOMMENDED, REQUIRED, SHOULD and SHOULD NOT in this document are to be interpreted as described in BCP 14 [RFC2119] [RFC8174] when, and only when, they appear in all capitals, as shown here.

1.5 Proof of conformity​

This section is non-normative

All participants and their solutions must prove that they conform to the Catena-X standards. To validate that the standards are applied correctly, Catena-X employs Conformity Assessment Bodies (CABs).

Core Service Provider B implementations of their own registration solution MUST prove their conformity by providing:

  • OpenAPI specifications for the CSP-B endpoints and the OSP callback endpoint they implement

2. Catena-X Registration API​

This section is normative

A Core Service Provider B MUST implement the following endpoints. The APIAPI An API is a way for two or more computer programs to communicate with each other. business logic, content, and structure are required; the root path can differ. Details of the respective MUST and SHOULD statements are described below.

2.1 Preconditions and dependencies​

The registration APIAPI An API is a way for two or more computer programs to communicate with each other. is exposed to the Internet.

The <base> notation indicates the base URL for an endpoint. For example, if the base URL is api.example.com, the URL https://<base>/api/administration/registration/network/partnerregistration will map to https://api.example.com/api/administration/registration/network/partnerregistration.

2.1.1 Available Data Types​

All Registration APIAPI An API is a way for two or more computer programs to communicate with each other. control-plane request and response messages MUST use the application/json media type. This excludes binary uploads to a storage-provider presigned URL.

The examples in this document are non-normative. The provided OpenAPI documents are normative machine-readable representations and MUST remain aligned with this specification.

2.1.2 API resources & endpoints​

The HTTPHTTP HTTP is an application-layer protocol for transmitting hypermedia documents (such as HTML). It was designed for communication between web browsers and web servers, but can also be used for other purposes. endpoints introduced in this standard MUST implement authentication and authorization.

2.3 Onboarding Service Provider​

2.3.1 Send registration status updates​

An Onboarding Service Provider MUST provide a callback endpoint to receive registration status updates from the Core Service Provider B. The OSP-hosted callback is defined in the OSP Registration Callback API.

Endpoint: POST {callbackUrl}

FieldTypeMandatoryDescription
externalIdstringMandatoryIdentifier originally provided in the partnerRegistration or participant-registration request
applicationStatusoneOf(RegistrationStatus, OSPParticipantRegistrationStatus)MandatoryRegistration status; the allowed enum depends on the registration flow
messagestringOptionalAdditional information, e.g. reason for rejection
bpnlstringMandatoryAs specified in CX-0010.
bpnastringOptionalAs specified in CX-0010.
bpnsstringOptionalAs specified in CX-0010.

All callback payloads MUST conform to OspRegistrationCallbackData. For registrations submitted through Initiate registration, applicationStatus MUST use the legacy RegistrationStatus values. For registrations submitted through Initiate participant registration by OSP, applicationStatus MUST use OSPParticipantRegistrationStatus.
